# 双星余烬：真实 3D 渲染迁移

## 审计与约束（2026-09-13）

- 基线：Phaser 3.90，Three.js 与 @types/three 已锁定 0.180.0；Vite 7.3.6。`npm test` 与 `npm run build` 通过；原有 Phaser 产物 1.31 MB / gzip 366 KB，有 500 KB 提示。
- `src/game/PixelBattleScene.ts` 是实际棋盘、输入、回合和舞台的控制器。`walkPath` 每步提交坐标；`playStageCombat` 调用纯 `resolveCombat` 一次，再在 cost / strike 接触时提交 HP。保留原提交节奏。
- `src/game/WorldScene.ts` 是世界地图导航；`VillageScene.ts` 是补给与出入口；`PreparationScene.ts` 提交编队并进入 battle。三个流程继续用现有 Phaser / DOM。
- 保护区：`src/game/rules/*`、`state.ts`、`save.ts`、`data/*`。迁移前 SHA-256 在 `hd2d-evidence/protected-before.sha256`。不改变玩法、RNG 分布或 v1/v2 存档迁移。
- 六类精灵各六个 256×256 姿态，统一底部锚点。复用原素材与职业映射；只有左右素材，因此镜头固定方位。
- 先迁移 starfall-bridge，再验证 moonlit-pass。地图均为原始 10×8；视觉坡道只在附表，不能被寻路读取。
- 工作区原本无 Git 提交，全为未跟踪文件。原代码快照保存于 `/tmp/embers-before-render-refactor.tgz`，不覆盖用户文件。

## 实施与验证计划

1. P0：引擎中立契约 → Adapter → RenderHost → Three 地形/单位/相机/拾取；挂接原 Scene 命令与逐步移动。验证规则不变量、旧档往返、两图可操作、失败回退、生命周期。
2. P1：统一输出、分档、材质、Fog / Bloom / DOF 与独立视觉粒子。用同一构图截图及帧时间验证。
3. P2：依据实际有序 cost / strike 结果播放地图镜头与职业演出，保留旧舞台。验证逐事件一次、MISS、反击、追击、致死、跳过及恢复。

浏览器测试使用隔离域名 `hd2d-render-qa.localhost:4174`，测试 fixture 不写玩家地址。实际验收结果在各阶段完成后追加，未验证项不计为通过。

## P0 实测

- 两章 3D 棋盘、格子拾取、原移动与旧舞台连通。第一章一次实测：凯尔两次命中各 9 点，敌方反击 MISS，e4 从 21 → 3；结束回合后回到 TURN 2。第二章所有 80 格中心的投影 → 拾取往返正确，并完成敌方回合。
- 经典/3D 切换单位状态完全相同；第二章 TURN 2 保存后刷新读取，单位状态相同。
- 连续 20 次 battle 场景重启：每次 1 个 renderer 容器、8 个标签、14 张 GPU 纹理、130 个几何体；未出现页面异常。GPU context loss 实测回退经典画面并成功重建，单位状态不变。
- 末段 fixture 通过真实移动触发首章占领胜利，返回世界 → 晨雾村 → 领取补给 → 出村 → 第二章剧情 → 整备 → 3D 开战；无页面异常。
- 已修复实测发现的地形合并属性不一致、前排 Billboard 抢占后排格子点击、Phaser shutdown 先销毁相机造成的回调错误。
- 上述为完整地图配置上的代表性实战与末段 fixture 验证，不等于穷尽两章所有路线。原存档未触碰。

## P1 实施与验证

- 独立显示设置键 `embers-display-settings-v1`；流畅/均衡/精细三档。流畅关闭实时阴影与后处理，保留脚底阴影与全部战术功能。
- 颜色贴图为 sRGB，凹凸数据为 NoColorSpace；石路、木桥、水、草、金属采用独立粗糙度/凹凸。新增程序化松树层次、边界瞭望屋；均为项目内原创几何/纹理，无外部素材引入。
- 后处理为线性颜色 RenderPass → 可选深度保护模糊 → Bloom → OutputPass（ACES + sRGB 一次输出）。深度通路复用角色当前帧 alpha 裁切材质。景深仅高档启用，选择移动/攻击目标时关闭；DOM HUD/血条不进入后处理。
- 雾、薄雾、粒子、辉光、景深与动态效果各自开关已实际操作；单位规则状态未变化。低档 WebGL 像素比 0.85，无后处理及实时阴影，仍能点选单位。选中移动时已确认景深 Pass 禁用。
- P0 性能：MacBook Air M5 / 24 GB / Tabbit Chromium 151，CSS 1461×907，DPR 2（P0 内部上限 1.5），月影峡道 9 单位；预热 10 秒，采集 60 秒 3600 帧，p95 18.6 ms / p99 18.7 ms，83 calls / 6992 triangles。此数据不代表 P1/P2 或其他设备。

## P2 实施与验证

- 应用侧 `CombatPlayback` 只提交规则解析器已经产生的有序 cost / strike。攻击接触时由原 Scene 写 HP，Three 时间线只读取结果；跳过会一次性排完尚未提交的同一结果，不重新抽取命中或伤害。
- 地图内镜头保存原战棋视角，结束 / 跳过 / 取消时恢复；六种现有精灵映射分别配置蓄力、接近、出手与收势。魔法投射物、斩击、命中闪光、局部停顿、暴击强化、MISS 闪避与致死退场均依赖实际事件。复用现有六姿态素材，未批量重绘角色。
- 1× / 2× / 跳过保留，减少动态效果会关闭运镜、震动和动态粒子，命中结果仍显示。昼夜 / 雨 / 雪纯视觉配置已通过 UI 切换；切换前后单位数据一致。
- 浏览器对照：同一 fixture、同一规则随机输入，分别运行经典舞台 / 3D 完整播放 / 3D 立即跳过。下列每组三种结果与有序事件完全一致，镜头恢复、临时对象隐藏、holds 清零；没有页面异常。

| 场景 | 最终 HP | 实际事件 |
| --- | --- | --- |
| 近战命中与追击 | 凯尔 20，e4 3 | 命中 9 → 反击 4 → 追击 9 |
| 近战未命中 | 凯尔 24，e4 21 | 三次 MISS，全部伤害 0 |
| 暴击致死 | 凯尔 24，e4 0 | 一次暴击 27，无致死后的反击 |
| 骑乘法术耗血 | 莱拉 20，e4 0 | 耗血 1 → 命中 11 → 耗血 1 → 追击 11 |

法术用例在隔离 fixture 中显式赋予 starfire，以覆盖 HP 消耗；这不改变实际角色初始技能。脚本：`scripts/playtest-presentation.js`。

- 在战斗中立即重启 Scene，旧异步演出不会继续写新场景状态；渲染中断使用 generation 标记隔离。演出中强制 GPU context loss，回到经典画面，既定最终 HP 仍正确。
- 后处理加入后再次交替高 / 低档并重启战场 20 次。低档稳定 31 张 GPU 纹理 / 129 个几何体，高档稳定 46 / 131；每次均 1 个渲染容器、8 个单位标签。数字是 Three 的已上传资源计数，不是显存字节。
- 实测平移与缩放后 75 个视口内格子拾取正确；屏幕外格子不接受点击。390×844 竖屏设置面板可用、无水平溢出。发现并修复横转竖时保留绝对相机距离造成两侧地图裁切，现保持相对缩放，80 格均在全图视口内。这是桌面浏览器尺寸模拟，不能替代手机实机触控测试。

## 接入文件与回退

| 位置 | 职责 |
| --- | --- |
| `src/presentation/contracts.ts`、`GameRenderAdapter.ts` | 引擎无关视图数据、稳定 ID、原规则事件投影、视觉地形采样 |
| `src/presentation/RenderHost.ts` | 动态加载、RAF、输入、尺寸变化、可见性、失败回退与资源生命周期 |
| `src/presentation/three/` | 地形、角色、光照、材质、后处理、环境、相机与战斗时间线 |
| `src/presentation/visual-config/`、`DisplaySettings.ts` | 两章视觉附表、职业动作配置、独立画面偏好 |
| `src/game/PixelBattleScene.ts` | 最小控制器接缝、原规则命令、原 HP 提交点与新旧画面切换 |

运行 `npm test`、`npm run build`；执行 `shasum -a 256 -c docs/hd2d-evidence/protected-before.sha256` 可核对 19 个规则 / 状态 / 存档 / 数据文件仍与迁移前逐字相同。开发入口 `window.__embers` 仅用于本地验收，生产构建移除。

游戏内“返回经典画面”会清理新渲染资源并显示当前权威状态。刷新时去掉 `renderer=three` 参数即可保持默认经典路径。关闭地图战斗设置只切换演出；关闭后处理或选择流畅档仍使用同一规则。此次没有存档 schema 迁移。

## 制作与验收边界

- 本轮落地 P0–P2 的棋盘渲染和演出功能。两张地图已有代表性实战、章节衔接及 fixture 验证；未穷尽所有策略、招募分支与完整自然通关路线。
- 树、屋、岩石和材质为程序化制作；角色仍是现有有限方向与六姿态素材。更完整的方向帧、手工职业动画、专门设计的地图美术属于后续内容制作，不能据此宣称商业级美术完成。
- 现有规则没有多目标伤害或召唤；没有为展示效果伪造这些规则。世界地图、村庄与整备继续用旧场景。
- 本机验证为 Tabbit Chromium；Firefox、Safari、iOS / Android 实机和限速冷加载尚未验证。GPU 资源计数不等于显存测量。跨浏览器与跨设备发布验收仍须补测。
