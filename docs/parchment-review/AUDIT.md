# 双星余烬 · 羊皮纸界面盘点与交互设计 v1

审核日期：2026-09-21。交付范围：独立设计原型；正式游戏界面等待本轮审核后再实施。

## 盘点结论

目前并非所有遗漏界面都“完全没有羊皮纸”。`src/chronicle-theme.css` 已为大部分旧窗口补了纸色和边框，但完整的材质、排版、透明立绘和交互状态尚未一致。

- **明确未接入主题**：3D 战场加载／失败层。`RenderHost` 将状态层挂在 body，未被 #hud 的羊皮纸主题覆盖。
- **已有纸色但素材误用**：主菜单设置、存档、技能说明等通用弹窗，直接裁切编队底板；现状会看到无关的“装备”文字和装饰干扰正文。
- **基础纸色后仍待完整统一**：村庄、对话、神殿、角色详情、预测、交换、结算与短反馈。
- **现有风格基准**：主菜单、编队、战场核心 HUD、战场菜单。沿用其暖纸、金边、藏蓝主按钮、深褐字和透明立绘，不重新设计整套风格。

## 既有风格与组件

- 1440×810 设计画布，桌面窗口等比缩放；不新增手机或触屏布局。
- 双页册直接复用 `menu-book.png`，单页使用 `unit-panel-refined.png`；按钮复用原有金边资源。正文避开金属边框、书脊和下部插画。
- 标题约 30–35px，正文 20–22px，说明约 16px；以宋体类衬线字体延续游戏既有气质。审核工具自身使用系统无衬线字体，和游戏画布区分。
- 深褐正文、暖金层级、藏蓝主操作；棕红表达风险、深绿表达已完成。不能只依赖颜色表达错误，必须同时写明原因。
- 使用现有凯尔、莱拉、米菈、诺克斯和蚀月骑士透明半身像。诺克斯保持红发斥候身份；不生成新角色，不引入带底板的卡图。
- 只读信息、未开放功能、禁用操作和加载失败都提供独立状态；按钮保留可见键盘焦点。

## 交互规则与实现边界

1. **模态返回**：Esc 或返回按钮关闭当前窗口，回到入口与原选中角色；正式接入时应恢复键盘焦点。原型关闭后回到参考背景，可通过“重新打开”复看。
2. **神殿**：Lv.3 门槛；先预览再确认，说明等级重置与保留项。原型用凯尔演示完整成功链，莱拉与米菈演示等级不足。角色能力增量示例取凯尔当前值与勇者职业基础值。
3. **角色详情**：能力与成长率分签。魔法示例切换到莱拉，攻击与回复有独立装备标记。角色内部页签保持同一角色；原型顶部审核状态条用于切换不同示例角色。敌方保持只读，尚未习得魔法沿用简短空状态文案。
4. **预测**：优先展示单次伤害、追击次数、命中、必杀、HP 与顺序；详细概率可折叠。数值为排版示例，正式接入仍取真实规则引擎。
5. **交换**：展示双方获得什么；确认前明确“结束当前角色行动”。无相邻同伴时确认禁用，取消不消耗行动。
6. **设置**：保留游戏支持的画质、光照、天气、雾、辉光、景深、粒子、减少动态、震动、闪光与音乐。主菜单不增加战场专用光照／天气能力。正式接入时保留现有高画质景深条件。
7. **记录册**：只整理现有数据；手动存档、支援及按键自定义继续显示待开放。自动存档读取的代表设计取主菜单入口；战场入口只展示自动保存状态。
8. **结算**：重复讨伐独立累计次数与经验，不计入两关主线，不重复发首次奖励。失败返回战前整备。示例数值不写入真实存档。
9. **短反馈**：正式游戏经验／回合提示依原有节奏淡出，遵守减少动态设置。为便于审核，原型停留在当前状态，允许手动查看升级；地图内演出只模拟提示及倍速状态，不播放新战斗。
10. **加载失败**：明确告知进度保留，战场仅提供 3D 重试。原型重试约 1 秒后显示恢复；不伪造百分比，也不模拟 2D 回退。
11. **覆盖确认**：取消优先，危险确认不自动聚焦；明确当前存档与覆盖后果。退出说明保留浏览器实际行为，不伪装成桌面进程退出。

## 现状证据与可信范围

现状截图目录：`public/evidence/`。共 21 张，参考分辨率 1440×810；清单见 `manifest.json`。

- 01 / 07 / 08 / 13：主菜单、编队、战场界面与书册菜单，作为既有风格基准。
- 02 / 09 / 19：设置和通用存档弹窗，证实底图误用和窗体不一致。
- 03–06 / 10–12：村庄、稳定对话、神殿、转职、详情、预测、交换。
- 14–18 / 21：3D 失败、胜利、边境预告、地图失败、新游戏确认与战败。
- 20：战斗核心 HUD 的静态场景参考，用作原型背景；**不是经验卡或回合横幅的现状截图**。

本轮使用新建审查标签页和仅内存的 localStorage 替身进行界面检查，不读取后覆盖用户真实存档。一部分难以自然到达的窗口通过开发场景方法及演示单位状态触发；胜败、预测、交换等截图证明相应真实界面如何渲染，不代表完整通关测试。短暂反馈、部分记录项、主菜单入口细分状态按源码补齐。

“对比当前界面”使用该类代表截图，不声称每个顶部子状态都有一张一一对应的实机截图。尤其结束远征、经验、招募、音频／辅助子页需结合源码说明理解。独立原型的场景底图为静态上下文，正式接入必须保留真实可交互地图与战场。

## 主要源码对应

- `src/main.ts`：主菜单设置、存档、覆盖确认、退出说明。
- `src/game/VillageScene.ts`：地点、抵达、进入与补给。
- `src/game/WorldScene.ts`：神殿、转职、地图失败、边境预告。
- `src/game/PreparationScene.ts`：技能、支援、出击顺序与只读提示。
- `src/game/PixelBattleScene.ts`：设置、详情、预测、转职、交换、菜单栏目、成长、回合及胜败。
- `src/game/ui/replica.ts`：共用对话框与角色素材映射。
- `src/game/ui/dialogue.ts` 与 `src/game/presentation/RenderHost.ts`：对话与 3D 状态层。
- `src/chronicle-theme.css` / `src/replica-theme.css`：目前的纸色补丁与素材背景来源。

## 审核方式

打开原型后，左栏选择界面；顶部切换状态，“对比当前界面”查看现状，“放大画布”查看细节。每页可标记“通过”或“需调整”并填写意见，刷新后保留；右上导出 Markdown 审核意见。

审核意见只保存在本机浏览器的原型站点存储中，不会提交到正式游戏、外部服务或聊天。浏览器间不自动同步，建议导出意见文件。关闭原型不影响游戏进度。
